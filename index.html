第 0 步 · 一键只读检查

只读
只检查，保留现有数据

脚本只读取已有文件和本机状态。配置、会话、登录状态和原文件都会保留。检查无需启动或重启 Claude，也不会发起联网探测。

这一步会查什么

一次列出配置、自动记忆和外接工具的来源与状态，并盘点本地会话记录。macOS 同时运行原版 claude-cleanup 的只读审计。

这一步检查用户级配置和本机记录。具体项目、公网出口和浏览器登录状态可在后面的条目单独核对。

要开始检查，请先在下载的项目文件夹启动本地手帖。电脑需有 Python 3.9 或更新版本。

macOS 双击 Start-Checklist.command，Windows 双击 Start-Checklist.cmd。浏览器打开后，点「开始只读检查」。

Linux 怎么打开

在项目文件夹打开终端，运行 python3 -B launch_checklist.py。-B 禁止写入 Python 字节码缓存。

    Claude 公网出口

    先检查
    先认准 Claude 实际走的线路

    公网出口地址是外部服务看到的网络地址。检查时以实际使用的 Claude 网页、桌面端或命令行为对象。

    核对步骤

    电脑直连，或整机走同一个出口
    1. 从运行 Claude 的同一台设备、同一网络环境，打开 公网地址检测站，记录回显地址和时间。
    2. 有全设备代理或虚拟专用网络（VPN）时，核对 Claude 使用的应用与检测请求都在它的接管范围内。还要查看应用排除项、浏览器独立代理和命令行代理设置。能查连接记录时，再对照实际走的线路。
    按应用、域名或规则分流
    1. 在你使用的代理软件、网络网关或企业网络日志里，找 Claude 已有连接。先查 claude.ai 和 anthropic.com，再按实际记录核对 claude.com、claudeusercontent.com、claude.app、claudemcpcontent.com 及相关子域。使用其他模型服务时，查实际服务域名。
    2. 记录连接命中的线路或节点。让出口检测请求使用这条已配置线路，再核对检测请求的连接记录，确认两者实际经过同一个出网节点或网关。
    3. 核对同一路线后，记录检测站本次回显的公网地址和时间。只能看到代理组名称、看不到最终出网节点时，保留「线路未核实」。同一线路也可能有不同地址，实际结果以本轮检测为准。
    4. 保留可刷新、可复查的连接记录。主站、实际使用的接口、资源域名及登录服务分别看命中规则。普通网页测速或代理节点延迟只能证明当时那条测试可用。需要排查间歇断线时，对照同一时间的现有应用日志和普通网络测试。
    在 Claude Code 的终端里核对
    1. 在已打开的 Claude Code 会话里输入 /status，看它显示的代理信息。若它在远程主机、容器或虚拟机里运行，切到同一个环境检查。代理配置以实际运行中的会话为准。
    2. 在同一环境的普通终端运行下方命令。macOS 和 Linux 用第一条；Windows 的 PowerShell 用第二条。输出只代表这条终端检测请求的公网地址。
    curl -q --max-time 10 --fail --silent --show-error https://ping0.cc/
curl.exe -q --max-time 10 --fail --silent --show-error https://ping0.cc/

    本地代理提供无需认证的网页代理端口时，可在 macOS 或 Linux 用下方命令明确指定它。先把示例的 8080 换成你的实际端口，再从连接记录确认检测请求和 Claude 命中同一线路。

    curl -q --noproxy "" --proxy "http://127.0.0.1:8080" --max-time 10   --fail --silent --show-error https://ping0.cc/

    这里 --proxy 为检测请求指定代理，--noproxy "" 确保它使用该代理。含账号密码的代理地址请留在自己的配置里。

    Claude Code 官方代理说明 · curl 官方命令手册
    检查域名解析、地址类型和系统时间
    1. 分开记录系统域名解析服务（DNS）、代理客户端的解析设置，以及浏览器是否启用了独立的加密解析。配置里的解析服务和实际查询结果分别记。代理日志或检测只能证明这一次查询经过的路径。
    2. 记录检测的是 IPv4（点分地址）还是 IPv6（冒号分隔地址）。两种地址分别核对。另一种地址或线路没有观察到时标「未核验」。
    3. 在系统「日期和时间」里核对本机时间、时区及是否自动校时。把时间用于对齐连接和错误日志。

    需要查看系统解析设置时，macOS 可用 scutil --dns，Windows 的 PowerShell 可用 Get-DnsClientServerAddress 查看各网卡配置的解析服务器。

    配置、记忆与身份来源

    重点检查
    查清 Claude 在哪里读到你的身份和偏好

    常见漏项是全局配置里的外部记忆连接，以及项目历史里的首条提示词。即使项目说明没有身份信息，也要把配置、记忆和已连接的工具分别检查。

    需要先盘点本机的配置、记忆和外接工具时，从第 0 步的一键只读检查开始。

    如何读检测结果

    「启动候选」表示路径或配置可能使文件在启动时载入。「按条件」表示与项目、路径、插件或会话状态相关。「已配置」表示找到了设置或工具声明。「仅留存」表示发现历史、本机凭据文件或备份。「未核验」表示静态文件无法确认的会话、账号或访问范围。

    命中文件里的邮箱格式或身份标签时，只报告线索类型。当前会话实际加载了什么、外接工具是否连接，以及云端账号记忆，按下方步骤分别核验。

    从实际使用的会话开始

    先确认 Claude 的版本、工作目录、是否在远程环境运行，以及用户级配置目录（默认 ~/.claude，可通过 CLAUDE_CONFIG_DIR 指定；Windows 默认是 %USERPROFILE%\.claude）。在已打开的 Claude Code 会话中查下面的面板。未运行时，可以只检查文件，无需启动会话来验证。

    1. /status 查看当前会话的设置来源。/context all 对照已经加载的指令和上下文。/memory 查看记忆入口和自动记忆状态。
    2. /mcp 查看外部工具连接。这里的外部工具协议称为 MCP。只查看名称和状态，避免为验证而调用记忆库或打开带凭据的连接详情。
    3. 为每条发现标记「已加载」「按条件加载」「可调用」「仅发现留存」或「未核验」。按下列清单核对实际内容、配置来源和触发条件。
    指令文档和规则

    查看组织托管文件、用户级 ~/.claude/CLAUDE.md，以及工作目录和各级父目录中的 CLAUDE.md、.claude/CLAUDE.md、CLAUDE.local.md。一并查用户级与项目级的 .claude/rules/、受支持或被引用的 AGENTS.md、.claude/AGENTS.md，以及指令通过 @路径 引用的文件和符号链接目标。

    工作目录里的指令、下级目录按需加载的指令，以及匹配路径才生效的规则，分别核对。使用额外工作目录时，也查会话是否加载了其中的指令。

    Claude Code 指令加载说明
    自动记忆和会话记录

    通过 /memory 定位实际记忆目录。默认位置是 ~/.claude/projects/<项目目录>/memory/，也要核对用于指定记忆位置的 autoMemoryDirectory。检查自动加载的索引 MEMORY.md 和可能按需读取的主题文件，特别留意姓名、别名、角色、工作习惯及历史项目。

    另查是否恢复了旧会话。对于本地聊天记录、history.jsonl 和独立归档，分别记下是否存在、当前会话是否实际引用。

    Claude Code 自动记忆说明
    全局状态和配置备份

    定位 Claude Code 实际使用的全局状态文件，默认是 ~/.claude.json。核对账号资料字段（oauthAccount）、本机用户和设备标识（userID、machineID）、项目记录（projects）和旧项目首条提示词（projects.<项目>.firstPrompt，如存在）。

    历史副本从 ~/.claude.json.backup、实际配置目录的 backups/ 和自己创建的备份找。只在本机用已知姓名、别名、邮箱、账号或组织标识核对旧资料。报告记字段名、来源与数量，账号缓存是否写入对话须另有载入证据。

    Claude Code 设置文件说明
    外接记忆、连接器和插件

    对照 /mcp、全局状态文件里的 mcpServers 和 projects.<项目>.mcpServers、项目根目录的 .mcp.json、组织管理的 managed-mcp.json，以及启动时传入的外部工具配置。

    同时查看已启用插件提供的外部工具、网页账号连接器及桌面端配置（如 claude_desktop_config.json）。记下工具是否已配置、已连接、曾被调用。历史对话里查到的笔记内容，按已有工具调用记录归因。

    外部工具的配置层级
    设置、启动参数和自动注入

    核对用户级 settings.json、项目的 .claude/settings.json 和 .claude/settings.local.json、组织托管设置（如 managed-settings.json），以及快捷方式、终端脚本、编辑器或封装工具实际传入的启动参数。重点查指定加载设置的 --settings、设置或附加系统提示词的 --system-prompt 和 --append-system-prompt 及对应文件参数、指定代理角色的 --agent、额外目录和会话恢复入口。

    如用过第三方启动器、配置切换器或自定义模型网关，查它们当前选中的配置和历史副本。重点记录指定服务端点的变量 ANTHROPIC_BASE_URL、认证变量（如 ANTHROPIC_AUTH_TOKEN）、读取凭据的辅助脚本设置（apiKeyHelper）是否存在。输出只记录字段与来源，实际使用的是哪套设置要按启动方式核实。

    查看启动钩子 SessionStart、发送提示词前的钩子 UserPromptSubmit，并核对用户级及项目级的技能（skills/ 下的 SKILL.md）、自定义命令（commands/）、子代理（agents/）、输出风格（output-styles/）和已启用的插件。按配置定位其读取的文档、脚本和外部工具，只审阅来源。操作系统用户名、主目录和项目路径也可能在会话中被工具看到。

    启动参数说明 · 启动钩子说明
    网页和桌面端账号侧个性化

    在已登录的 Claude 网页或桌面应用里查看「设置 → 你的 Claude」中的个人指令与记忆，旧界面也可能有单独的「记忆」页。进入实际使用的项目，再查项目指令、知识文件和所用连接器。

    账号侧看不到或本轮无访问权限的内容标为「未核验」。整理公开检查结果时，只写来源和是否有匹配。

    交给 Codex

    只读核对 Claude 能得知我身份和偏好的来源。先确认实际工作目录、Claude 客户端、用户级配置目录和启动方式，再查各级指令文件、规则与引用、自动记忆、全局状态和历史备份、项目首条提示词、外部记忆工具各级配置、插件及启动钩子。网页或桌面账号侧核对个人指令、记忆与项目知识。按来源报告已加载、按条件加载、可调用、仅发现留存或未核验；只输出路径类别、字段名和计数，保留当前会话、配置与记忆。不要重启 Claude 或调用外部记忆库来测试。

    完整备份

    按需检查
    先确认备份能读，再处理本机数据

    备份清单有差异时，先检查拟恢复文件和可用副本。备份对象以本轮确认的实际目录为准。

    核对步骤

    核对备份目录能否读取、清单是否一致，并用独立副本校验拟恢复文件。换机器或接手备份时，先复制到新目录验证。

    把「只读审计」「备份已核对」「已处理」和「处理后已复查」分别记下来。后两项应附实际处理范围、跳过或失败项和复查结果。指定保留的会话按自己的归档清单核对。

    交给 Codex

    只读核对我指定的备份和清单。报告实际文件数量、差异和可以独立核实的恢复范围。若有差异，保留原备份和清单。

    会话归档

    按需检查
    挑出要留的会话，再做逐文件校验

    本地 Claude Code 的会话、浏览器里的对话和云端记录各有不同存储位置，应先确认要保留哪一类。

    核对步骤

    对本地会话保留独立副本，逐份确认能读取并与原文件比对。需要导出时，复制到新目录，并保留原始会话。

    交给 Codex

    只读确认 Claude 本地会话的位置，核对要保留的会话。等我另行要求导出时，再复制到新目录、逐文件校验并返回路径。

    缓存和日志

    按需检查
    按客户端和实际目录识别可清理项目

    当前运行中的客户端会持续写入一些缓存和日志。先把范围、项目类型和大小查清楚。

    核对步骤

    macOS 的原版 claude-cleanup 审计已整合进第 0 步的只读检查。运行一次即可列出缓存和日志候选、桌面端数据位置、相关进程数及其他审计状态。

    查看整合审计的范围

    原版审计盘点 macOS 的默认目录。实际使用的项目和自定义配置目录由同一脚本的配置检查部分另外核对。桌面端数据位置和缓存候选只作只读记录。

    查看下载与运行命令 · 原版来源与用法
    交给 Codex

    按我的操作系统和 Claude 客户端版本，只读核对缓存与日志。macOS 上可运行手帖第 0 步的整合脚本，报告原版审计与配置检查的结果。保留全部文件和当前 Claude 状态。

    桌面应用数据

    按需检查
    区分应用设置和站点登录数据

    桌面端的数据位置和凭据管理方式随系统和客户端版本变化。检出本地文件只表示对应位置有数据。

    核对步骤

    先查桌面客户端实际使用的站点存储和系统凭据条目，记录位置及存在状态。需要退出登录时，先确定要处理的账号和应用范围。

    区分官方应用、第三方外壳及旧副本

    确认当前桌面应用的安装来源、版本和是否仍在运行。用过第三方 Claude 外壳或启动器时，另外盘点它自己的程序入口、后台或自启动服务、配置及数据目录。备份或废纸篓里能找到的配置、站点数据和认证资料按历史副本报告，只记录类型和来源。

    交给 Codex

    按我实际使用的 Claude 桌面客户端和系统，只读核对本机站点存储与凭据条目。只输出存在状态，保留当前设置及登录。

    命令行登录凭据

    按需检查
    在实际运行 Claude Code 的环境里查

    本机终端、远程终端和容器可能使用不同配置。检测时只记录发现了哪些凭据来源。

    核对步骤

    检查当地系统的凭据管理器、Claude Code 配置及启动环境。登记凭据来源和查到的状态，避免展示令牌和密码。

    核对安装来源及卸载后的命令入口

    在实际使用的终端里列出命令解析到的位置。macOS 或 Linux 用 type -a claude 查看可找到的入口；Windows 的 PowerShell 用 Get-Command claude -All。曾同时用多个安装工具时，分别核对各自的安装清单。卸载后在新终端重新核对，并单独记录桌面应用和会话归档的状态。

    交给 Codex

    在 Claude Code 实际运行的环境中只读核对凭据来源、配置和认证变量是否存在。只报告找到、未找到或无法核实，保留现有登录。

    浏览器会话

    按需检查
    这台电脑装了哪些浏览器，就逐个查哪些

    Safari、Chrome、Comet 优先核对。Edge、Firefox、Brave 和其他已安装的浏览器也要列入。个人、工作等用户配置分别记录结果。

    核对步骤

    1. 先列出这台电脑上安装和使用过的浏览器。可从 macOS 的「应用程序」、Windows 的「已安装的应用」或 Linux 的应用菜单找。
    2. 按下面的入口打开网站数据列表，分别搜索 claude 和 anthropic。核对完整域名和子域名，例如 claude.ai、claude.com、claudeusercontent.com 和 anthropic.com。
    3. 按「浏览器 / 用户配置」记录「发现网站数据」「未发现」「未核验」或「未安装」。站点登录数据、浏览历史和恢复的标签页分别记录。无法确认某个配置是否在当前列表范围内时，标记「未核验」。
    Safari（macOS）

    菜单栏选「Safari 浏览器 → 设置 → 隐私 → 管理网站数据」，在搜索框里输入域名。用过多个用户场景时，先在「设置 → 用户场景」确认场景清单，再核对当前网站数据列表的范围。

    Apple 网站数据说明 · Safari 用户场景说明
    Google Chrome

    切到要查的用户配置，在地址栏输入 chrome://settings/content/all。也可从「设置 → 隐私和安全 → 第三方 Cookie → 查看所有网站数据和权限」进入。Cookie 是网站保存在浏览器里的数据。

    Chrome 网站数据说明
    Comet

    切到要查的用户配置，在地址栏试用 comet://settings/content/all。入口如随版本变化，可在 Comet 设置的「隐私和安全」中搜索「网站数据」或「站点设置」，进入按网站列出的数据页面。

    Comet 隐私设置说明
    Microsoft Edge

    切到要查的用户配置，打开「设置 → 隐私、搜索和服务 → Cookie → 查看所有 Cookie 和站点数据」，在网站列表里搜索。

    Edge 网站数据说明
    Mozilla Firefox

    打开「设置 → 隐私与安全」，找到「Cookie 和网站数据」或「浏览数据」，进入「管理数据」或「清除指定网站的数据」的列表。在列表里搜索并记录结果。

    Firefox 网站数据说明
    Brave

    切到要查的用户配置，在地址栏输入 brave://settings/content/all。也可从隐私和安全设置下的「网站和防护设置」寻找网站数据列表。

    Brave 网站数据说明
    其他已安装的浏览器

    从浏览器设置搜索「网站数据」或「站点数据」，打开按网站列出的列表。多用户配置、其他系统用户或浏览器存档超出本轮访问范围时，记录具体范围。

    使用 Gmail 地址时，核对实际登录方式

    如果用邮件链接登录，按 Claude 站点数据检查。若选择过「使用 Google 登录」，还可以在 Google 账号的第三方连接里查看授权状态。浏览器站点数据和账号授权分别登记，只读检查保留当前会话。

    Claude 登录方式 · Google 第三方连接说明

    这一步只搜索和记录。找到网站数据表示当前列表里有本地记录，登录会话是否仍有效需要另外核实。

    交给 Codex

    先只读列出这台电脑上已安装或有可访问用户配置的浏览器，优先核对 Safari、Chrome 和 Comet，也覆盖 Edge、Firefox、Brave 及其他实际安装的浏览器。逐个可访问的用户配置查询 Claude 和 Anthropic 的网站数据。按浏览器及配置报告「发现」「未发现」「未核验」或「未安装」，只报告域名和状态，保留已打开的标签页、网站数据和登录状态。
