Claude 公网出口

先检查
先认准 Claude 实际走的线路

公网出口地址是外部服务看到的网络地址。检查时以实际使用的 Claude 网页、桌面端或命令行为对象。

核对步骤

电脑直连，或整机走同一个出口
  1. 从运行 Claude 的同一台设备、同一网络环境，打开 公网地址检测站，记录回显地址和时间。
  2. 有全设备代理或虚拟专用网络（VPN）时，核对 Claude 使用的应用与检测请求都在它的接管范围内。还要查看应用排除项、浏览器独立代理和命令行代理设置。能查连接记录时，再对照实际走的线路。
按应用、域名或规则分流
  1. 在你使用的代理软件、网络网关或企业网络日志里，找 Claude 已有连接。网页版可搜 claude.ai，直连 Anthropic 的命令行可搜 api.anthropic.com。使用其他模型服务时，查实际服务域名。
  2. 记录连接命中的线路或节点。让出口检测请求使用这条已配置线路，再核对检测请求的连接记录，确认两者实际经过同一个出网节点或网关。
  3. 核对同一路线后，记录检测站本次回显的公网地址和时间。只能看到代理组名称、看不到最终出网节点时，保留「线路未核实」。同一线路也可能有不同地址，实际结果以本轮检测为准。
在 Claude Code 的终端里核对
  1. 在已打开的 Claude Code 会话里输入 /status，看它显示的代理信息。若它在远程主机、容器或虚拟机里运行，切到同一个环境检查。代理配置以实际运行中的会话为准。
  2. 在同一环境的普通终端运行下方命令。macOS 和 Linux 用第一条；Windows 的 PowerShell 用第二条。输出只代表这条终端检测请求的公网地址。
curl -q --max-time 10 --fail --silent --show-error https://ping0.cc/
curl.exe -q --max-time 10 --fail --silent --show-error https://ping0.cc/

本地代理提供无需认证的网页代理端口时，可在 macOS 或 Linux 用下方命令明确指定它。先把示例的 8080 换成你的实际端口，再从连接记录确认检测请求和 Claude 命中同一线路。

curl -q --noproxy "" --proxy "http://127.0.0.1:8080" --max-time 10   --fail --silent --show-error https://ping0.cc/

这里 --proxy 为检测请求指定代理，--noproxy "" 确保它使用该代理。含账号密码的代理地址请留在自己的配置里。

交给 Codex

只读核对我使用的 Claude 客户端实际走的网络线路。先根据我的系统和网络工具查已有连接，再用同一出口的检测请求核对公网地址。分别标出规则、实际连接和检测站回显；没有同线路证据时标为未核实。保留当前网络配置与登录。

完整备份

按需检查
先确认备份能读，再处理本机数据

备份清单有差异时，先检查拟恢复文件和可用副本。备份对象以本轮确认的实际目录为准。

核对步骤

核对备份目录能否读取、清单是否一致，并用独立副本校验拟恢复文件。换机器或接手备份时，先复制到新目录验证。

交给 Codex

只读核对我指定的备份和清单。报告实际文件数量、差异和可以独立核实的恢复范围。若有差异，保留原备份和清单。

会话归档

按需检查
挑出要留的会话，再做逐文件校验

本地 Claude Code 的会话、浏览器里的对话和云端记录各有不同存储位置，应先确认要保留哪一类。

核对步骤

对本地会话保留独立副本，逐份确认能读取并与原文件比对。需要导出时，复制到新目录，并保留原始会话。

交给 Codex

帮我确认 Claude 本地会话的位置，核对要保留的会话。如果我指定了项目或会话，导出到新目录，再逐文件校验并返回路径。

缓存和日志

按需检查
按客户端和实际目录识别可清理项目

当前运行中的客户端会持续写入一些缓存和日志。先把范围、项目类型和大小查清楚。

核对步骤

macOS 用户可使用 claude-cleanup 做只读审计。其他系统先按本机客户端版本确认位置。需要执行清理时，先正常退出客户端，备份后核对具体范围。

macOS 的只读审计指令

获取并核对工具源码后，从工具说明文件所在的目录运行下方命令。--audit 只列出检测结果。

python3 scripts/claude_cleanup.py --audit
已核对版本的工具说明
交给 Codex

按我的操作系统和 Claude 客户端版本，只读列出明确可再生的缓存及日志，报告路径和大小。待我明确授权后，再按本机适用流程处理并复查。

桌面应用数据

按需检查
区分应用设置和站点登录数据

桌面端的数据位置和凭据管理方式随系统和客户端版本变化。检出本地文件只表示对应位置有数据。

核对步骤

先查桌面客户端实际使用的站点存储和系统凭据条目，记录位置及存在状态。需要退出登录时，先确定要处理的账号和应用范围。

交给 Codex

按我实际使用的 Claude 桌面客户端和系统，只读核对本机站点存储与凭据条目。只输出存在状态，保留当前设置及登录。

命令行登录凭据

按需检查
在实际运行 Claude Code 的环境里查

本机终端、远程终端和容器可能使用不同配置。检测时只记录发现了哪些凭据来源。

核对步骤

检查当地系统的凭据管理器、Claude Code 配置及启动环境。登记凭据来源和查到的状态，避免展示令牌和密码。

交给 Codex

在 Claude Code 实际运行的环境中只读核对凭据来源、配置和认证变量是否存在。只报告找到、未找到或无法核实，保留现有登录。

浏览器会话

按需检查
逐个浏览器配置查看网站数据

同一浏览器的多个用户配置可有独立的网站数据。曾经登录 Claude 的配置才需要列入检测。

核对步骤

在浏览器的「隐私」或「网站数据」设置里分别搜索 claude.ai 和 anthropic.com，记录匹配状态。需要移除时，先确认具体浏览器配置和站点。

交给 Codex

在我指定的浏览器及用户配置里只读查找 Claude 与 Anthropic 的网站数据，按配置报告结果，保留已打开的标签页和登录状态。
