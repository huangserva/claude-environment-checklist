# 逐条复核「建议复核」清单

第 0 步完成后，展开本地网页的「逐条复核」，用浏览器工具读出「本次复核清单」文本框的值。该清单包含本轮标识（`scan_id`）以及每条标记项的编号、类别、来源、原始状态和标记原因。网页打开在哪台电脑，复核就以那台电脑提供的证据为准。

1. 按清单顺序处理每个编号。对照原记录的来源和标记原因，只读查看必要的本地证据。对路径别名，用启动器使用的配置目录、用户主目录或已确认的工作目录定位。无法可靠还原路径时，保留原别名并记录证据不足。对浏览器留存，使用该浏览器配置的域名索引结果。站点数据或已配置的工具只说明存在对应线索。
2. 针对当前 Claude 会话，只使用可确定属于同一会话的已有证据，例如已经显示的上下文来源，或能对上该来源的成功读取事件。不同会话的事件、文件名出现在提示词中、配置声明、备份存在、工具调用请求本身，均不足以证实读取。找不到唯一的当前会话时，继续复核全部来源并标记相关读取证据不足。保留现有进程和会话，使用已经取得的记录。
3. 每条写清来源、为何被标记、核对到的证据和结论。敏感值、邮件地址、凭据、正文和私密绝对路径留在本机。仅报告证据位置或类型及必要的脱敏摘要。重复记录可引用主记录编号，每条依然保留自己的结论。

## 结论分类

| 结果字段的取值 | 网页显示 | 需要的证据 |
| --- | --- | --- |
| `read` | 已证实当前会话读取 | 可归属到目标会话的上下文来源，或对上编号来源的成功读取事件。 |
| `configured` | 已配置，实际读取待核验 | 有当前配置或可采用来源，尚无直接读取证据。 |
| `historical` | 仅历史留存 | 本轮仅在备份、归档或旧记录中发现该来源。 |
| `example_or_duplicate` | 模板或重复记录 | 可以确认是示例占位内容，或与已复核条目重复。重复项在证据中引用主记录编号。 |
| `insufficient` | 证据不足 | 无法定位、访问或确认来源，或现有记录不足以得出更具体结论。说明缺少什么。 |

只有同时取得本次会话的读取证据和来源确属旧资料的依据，才填写该条的 `old_evidence`。账号在服务端的关联状态独立于本机复核。

## 回填网页

把下面格式的结构化结果填入同一网页的「Codex 复核结果」文本框，点击「核对并显示复核结果」。每条都必须有 `id`、结论分类（`verdict`）、证据摘要（`evidence`）和结论（`conclusion`）。只有取得直接读取证据时才提供当前会话的脱敏标识（`target_session`）及该条的 `session_evidence`。

```json
{
  "scan_id": "从本次清单原样带回",
  "target_session": "当前会话的脱敏标识",
  "reviews": [
    {
      "id": "R001",
      "verdict": "read",
      "evidence": "已有上下文记录明确列出该来源。",
      "conclusion": "已证实当前会话读取这份资料。",
      "session_evidence": {
        "kind": "context_record",
        "session_ref": "当前会话的脱敏标识",
        "reference": "可核对的已有事件或记录位置"
      },
      "old_evidence": "可核对的旧会话或归档出处。"
    },
    {
      "id": "R002",
      "verdict": "historical",
      "evidence": "字段在有明确备份来源的文件中存在。",
      "conclusion": "本轮仅在历史备份中发现这个来源。"
    }
  ]
}
```

`context_record` 表示已有上下文来源记录，`successful_read` 表示已有成功读取记录。示例只演示格式，按本轮清单完整填入所有编号。没有确认读取时，省略会话字段和 `old_evidence`。零标记项时直接报告该轮复核数量为零。

确认网页显示「复核完成」和全量计数后，再给用户报告。说明复核了多少条、各类结论有多少条，以及哪些旧资料的读取得到了证实。没有取得直接证据时，说明本轮未证实。页面结果保留在浏览器本页内存里。保持检查只读，保留原文件、会话、配置与备份。
